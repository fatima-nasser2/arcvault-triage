# ArcVault AI Intake & Triage

An n8n workflow that takes an unstructured customer message, classifies it with an LLM, extracts the key entities, routes it to a team queue, flags it for human review when needed, and writes a structured JSON record.

| Deliverable (brief §4) | Where |
|---|---|
| 4.1 Working workflow | `workflow/arcvault_triage.json` (import into n8n) + screenshots / Loom |
| 4.2 Structured output | `output/records.json` (generated by `scripts/run_samples.py`) |
| 4.3 Prompt documentation | `docs/PROMPTS.md` |
| 4.4 Architecture write-up | `docs/ARCHITECTURE.md` |

## Run it (about 10 minutes)

1. Create an OpenAI API key at platform.openai.com (pay-as-you-go; the full sample run costs about $0.03). Groq or Ollama also work, see `.env.example`.
2. Set up the environment:
   ```bash
   cp .env.example .env              # paste your key into LLM_API_KEY
   docker compose up -d              # n8n on http://localhost:5678
   ```
3. Open http://localhost:5678, create the local owner account, then **Workflows → Import from File → `workflow/arcvault_triage.json`**, then **Publish** (n8n 2.x's word for "activate").
4. Send the samples:
   ```bash
   python scripts/run_samples.py --only-required   # the 5 from the brief
   python scripts/run_samples.py                   # + 3 edge cases
   python scripts/run_samples.py --repeat 3        # consistency check
   ```
   The script prints a table against the expected labels and writes `output/records.json`. The workflow also appends to `output/queue_<Queue>.jsonl` and `output/all_records.jsonl`.

**Already have n8n installed (npm)?** Skip Docker. Create `C:\data\output` (or `/data/output`), then start n8n from the project folder with the `.env` values loaded plus `N8N_BLOCK_ENV_ACCESS_IN_NODE=false` and `N8N_RESTRICT_FILE_ACCESS_TO=<that folder>`. PowerShell one-liner:
```
Get-Content .env | Where-Object { $_ -match '=' -and $_ -notmatch '^#' } | ForEach-Object { $k,$v = $_ -split '=',2; Set-Item "env:$($k.Trim())" $v.Trim() }; $env:N8N_BLOCK_ENV_ACCESS_IN_NODE="false"; $env:N8N_RESTRICT_FILE_ACCESS_TO="C:\data\output"; n8n
```

**No API key?** Run `python scripts/mock_llm.py` and point `.env` at it (see `.env.example`). The mock returns keyword-based canned answers. It is for testing the plumbing only and is **not** the classifier.

## Layout

```
workflow/src/*.js         one file per Code node: the real logic, readable and diffable
workflow/build_workflow.py  builds arcvault_triage.json from src/ and regenerates docs/PROMPTS.md
data/samples.json         5 brief samples + 3 edge cases, with expected labels
scripts/run_samples.py    ingestion driver + label check + consistency check
scripts/mock_llm.py       offline OpenAI-compatible stub
```

Edit the JS in `src/`, then run `python workflow/build_workflow.py` and re-import the workflow.

|---|---|---|---|---|---|---|
| 1 | Bug Report | High | 0.90–0.92 | Engineering | no | Single user, 403 after an update. High priority but not an outage. |
| 2 | Feature Request | Low | 0.95 | Product | no | |
| 3 | Billing Issue | Medium | 0.92–0.95 | Billing | no | Disputed amount is $1,240 − $980 = **$260**, under the $500 rule (ARCHITECTURE §3) |
| 4 | Technical Question | Low | 0.85–0.92 | Support | no | |
| 5 | Incident/Outage | High | 0.95–0.96 | **Escalation** | yes | Category plus the phrases "stopped loading" and "Multiple users" |
| edge-1 | Technical Question ×2, Bug Report ×1 | Low | 0.40–0.60 | **Escalation** | yes | Too vague: the low-confidence fallback |
| edge-2 | Billing Issue | Medium | 0.95 | **Escalation** | yes | Disputed $2,400 > $500 |

All 8 matched the expected routing in every run. Each category was identical across runs except edge-1, which still escalated every time (see ARCHITECTURE §3).

The submitted records are `output/records.json` (the 5 required) and `output/records_with_edge_cases.json` (all 8). Screenshots of each step are in `screenshots/`.

## What went wrong during the build, and the fixes

- **The model echoed our own label** as "evidence" and **padded summaries** with invented impact statements. Fixed in prompt `enrich-v4` (details in `docs/PROMPTS.md`, Iteration log).
- **Keyword false positives**: a bare `down` matched "download" and "dropdown". Fixed with word-boundary phrases, and kept as edge case 3.
- **Hallucinated identifiers**: the enricher can invent IDs, so the code drops any identifier not found verbatim in the message.
- **Confidence format drift**: models sometimes answer `85` instead of `0.85`, so the parser normalises it.
- **One failed LLM call killed the run** and lost the message. LLM nodes now retry 3× and then pass the error on, and the record is escalated as `classification_failed`.
- **Windows encoding**: the build script read files as Windows-1252 and garbled "—" in the prompts. It now reads and writes UTF-8 explicitly.
- **n8n file node** can't create sub-folders, so the queue files are flat (`queue_<Queue>.jsonl`).

## Assumptions
- "Billing error > $500" means the disputed difference, not the invoice total.
- Escalated records go *only* to the Escalation queue, as the brief says. In production I'd page on-call in parallel (ARCHITECTURE §3).
- Confidence is the model's self-reported score, anchored by a rubric. It is not calibrated.
- Message 1's "arcvault.io/user/jsmith" is treated as an account identifier/URL. No customer lookup is done.
